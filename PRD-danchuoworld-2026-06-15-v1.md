# PRD — Персональный сайт-дашборд «о себе»

**Рабочее название:** danchuo.world  
**Версия:** v1 (первая, осознанно небольшая)
**Дата:** 2026-06-15
**Автор / владелец:** DANCHUO
**Статус:** черновик к согласованию

---

## 1. Обзор и цели

Публичный персональный сайт-дашборд на собственном домене: «живая визитка», построенная вокруг **календаря**, где центральный элемент — **текущий день** и его статистика, а вокруг — компактные виджеты (Spotify, проекты, соцссылки, тема). Часть данных подтягивается автоматически (Apple Health, Spotify), часть вводится вручную в один тап через iOS-шорткаты.

**Цели v1:**
- Собрать рабочее ядро «Сегодня + календарь» без застреваний на трудных интеграциях.
- Автоматизировать дешёвые источники (Health через Shortcut, Spotify через API).
- Заложить архитектуру тем («волн») и расширяемого чеклиста с первого дня.
- Зафиксировать сложные хотелки (экранное время, Вуш/Юрент, книги, плёнка, 3D) как высокоприоритетный бэклог, не блокируя релиз.

**Нецели v1:** геймификация, 3D-конвертация артефактов, админ-панель, загрузка фото через UI, ретроспективная история Spotify.

---

## 2. Целевая аудитория

- **Читатель (публичный):** любой посетитель домена. Доступ только на чтение. Видит публичный дашборд.
- **Владелец (один — ты):** единственный, кто пишет данные. Доступ к write-эндпоинтам только по токену. В v1 нет UI для записи (кроме шорткатов и прямых вызовов API).

## 3. Технический стек

| Слой | Решение | Причина                                                                             |
|---|---|-------------------------------------------------------------------------------------|
| Backend | **Quarkus (Kotlin)**, монолит, REST JSON API | Монолит                                                                             |

## 4. Основные функции v1

Каждая фича: описание → acceptance criteria → technical considerations.

### 4.1. Каркас экрана (bento-сетка)
**Описание.** Главный экран — bento-сетка модульных плиток. Центральная крупная плитка — «Сегодня». Рассчитан на 16" (~1512px) без вертикального скролла для основного борда; галереи и архивы — за отдельными роутами/панелями.

**Acceptance criteria:**
- На ширине ≥1440px главный борд (Сегодня + Календарь + ряд статов + now-playing + индикатор темы) виден без скролла.
- На меньших ширинах сетка деградирует в скролл-колонку без потери данных (graceful fallback).
- Все цвета/шрифты/фон берутся из активной темы (см. 4.9), не хардкодятся.

**Technical considerations.** CSS Grid (bento), все визуальные значения — через CSS-переменные (design tokens). Никаких инлайн-цветов.

### 4.2. Плитка «Сегодня»
**Описание.** Центральный фокус: крупная дата + ключевые статы выбранного дня — шаги, сон, тренировка(и), now-playing, отметки чеклиста, признак «монстр», (позже) экранное время.

**Acceptance criteria:**
- По умолчанию показывает сегодняшний день.
- При клике на день в календаре (4.3) перерисовывается на выбранную дату.
- Отсутствующие данные показываются как «нет данных», не как 0 или ошибка.

**Technical considerations.** Источник — `GET /api/days/{date}` (агрегат). «Монстр» рендерится как картинка банки выпитого вкуса + акцент-цвет дня (или нейтрально, если не пил).

### 4.3. Календарь-навигатор (±15 дней)
**Описание.** Главное взаимодействие сайта. Окно ~месяц: текущий день ±15. Ховер по дню = мини-превью статов; клик = перефокус плитки «Сегодня» на этот день.

**Acceptance criteria:**
- Видны дни от (today − 15) до (today + 15).
- Ховер по дню показывает мини-сводку (шаги, сон, отметки) без перехода.
- Клик меняет фокусный день у плитки «Сегодня».
- Дни с данными визуально отличимы от пустых; «монстр»-дни имеют акцент.

**Technical considerations.** Диапазон тянуть одним запросом `GET /api/days?from=&to=` и кэшировать на клиенте. Будущие дни рендерятся пустыми.

### 4.4. Apple Health (шаги, сон, тренировки)
**Описание.** Данные из HealthKit заливаются iOS-шорткатом по расписанию 12:00 / 18:00 / 24:00. Облачного API у Apple нет — данные пушит устройство.

**Acceptance criteria:**
- `POST /api/ingest/health` (под токеном) принимает за дату: `steps`, `sleepMinutes`, список `workouts`.
- Повторный POST за ту же дату — идемпотентный upsert (перезапись, не дубли).
- Вечерний прогон (24:00) фиксирует полный день; дневной — сон прошлой ночи.

**Technical considerations.** Health-шорткат **не требует ввода** → крутится по time-automation полностью без участия владельца. Тело — JSON. Тренировки — отдельная сущность (4.x модель данных).

### 4.5. Spotify (now-playing / недавние / топы)
**Описание.** Живой опрос Spotify Web API: что играет сейчас, последние треки, топы за период. Собственную историю в v1 **не копим**.

**Acceptance criteria:**
- `GET /api/spotify/now-playing` возвращает текущий трек или «ничего не играет».
- `GET /api/spotify/recent` — последние проигранные (лимит API — 50).
- `GET /api/spotify/top?range=short|medium|long` — топ-треки за ~4 недели / 6 мес / всё время.
- now-playing обновляется при загрузке страницы (живой), без участия расписания шорткатов.

**Technical considerations.** OAuth Authorization Code; **refresh-токен хранится на бэке в зашифрованном виде** (см. безопасность). Бэк сам обновляет access-токен. Ограничение API: recently-played — только последние 50, посуточной истории нет (см. бэклог 6.5).

### 4.6. Чеклист дисциплины (расширяемый) + «монстр»
**Описание.** Набор ежедневных бинарных пунктов (растяжка, чтение, …), расширяемый без релиза. Плюс **«монстр» — какой конкретный вкус энергетика выпит в этот день** (банка с картинкой), либо «не пил». Картинка банки и её цвет придают день акцент.

**Acceptance criteria:**
- Пункты чеклиста задаются данными (можно добавить новый пункт без деплоя кода).
- Вкусы монстра задаются данными (сущность `MonsterFlavor` с картинкой/цветом), новый вкус добавляется без деплоя.
- `POST /api/ingest/daily` (под токеном) принимает за дату: отметки пунктов, `monsterFlavorKey: string | null` (null = не пил), (позже) `screenTimeMinutes`, `readingProgressPercent`.
- В плитке «Сегодня» — картинка банки выпитого вкуса; в превью календаря день получает акцент-цвет этого вкуса (или нейтральный, если не пил).

**Technical considerations.** Ввод — отдельный **интерактивный iOS-шорткат в один тап**: меню теперь со списком вкусов + «не пил» (Choose from Menu) + Ask for Input для чисел, далее POST. Запускается с домашнего экрана/виджета; опционально дневное напоминание. Полностью без участия не крутится (нужен ответ владельца). В v1 один вкус на день (мультивыбор — тривиальное расширение через связь many-to-many). Набор вкусов сидится статикой/через API, админка не нужна.

### 4.7. Проекты (компактный выпадающий блок)
**Описание.** Список проектов по годам/кварталам в небольшом раскрывающемся блоке, растущем по мере наполнения.

**Acceptance criteria:**
- `GET /api/projects` отдаёт проекты, сгруппированные/сортируемые по году и кварталу.
- Каждый проект: заголовок, год, (опц.) квартал, (опц.) ссылка, (опц.) описание.

**Technical considerations.** В v1 наполняется сид-конфигом / прямым вызовом API (админки нет).

### 4.8. Соцссылки + избранное фото + marquee артефактов
**Описание.** Блок ссылок на соцсети; одна избранная (hero) фотография на главном; **бегущая строка (marquee) артефактов жизни с подписями** (футболки, ракетка для бадминтона, камера, айфон, спортивные очки) — в v1 это статичные PNG.

**Acceptance criteria:**
- `GET /api/social-links` отдаёт ссылки с иконками и порядком.
- На главном виден один hero-снимок (сид-ассет).
- Marquee бесконечно прокручивает артефакты с подписями; PNG лежат как статические ассеты.

**Technical considerations.** Артефакты — фиксированный небольшой набор, сидится статикой, админка не нужна. 3D-конвертация — бэклог (6.7).

### 4.9. Система тем («волна»)
**Описание.** Визуальный стиль (палитра, типографика, фон) сменяем по релизам в честь периода жизни. В v1 — одна тема, но архитектура готова к смене.

**Acceptance criteria:**
- Все визуальные значения вынесены в design tokens (CSS-переменные).
- `GET /api/theme/active` отдаёт токены активной темы; ровно одна тема активна.
- Смена активной темы меняет вид всего сайта без правок компонентов.

**Technical considerations.** Токены в БД как JSONB; фронт инжектит их в `:root`. Заложить с первого дня — задним числом дорого.

## 6. Высокоприоритетный бэклог (хочется сильно, способ TBD)

> Внесены в PRD, чтобы не потерять; **не блокируют v1**.

1. **Экранное время (Apple).** Нет в HealthKit и экспорте; framework DeviceActivity/FamilyControls наружу сырьё не отдаёт. Fallback — ручной ввод (поле уже есть в DayRecord). Автоматизация — отдельный research-заход.
2. **Вуш/Юрент — факт поездки.** Публичного API нет. Реалистично — ручной лог (сущность Ride). 
3. **Вуш/Юрент — маршрут на карте.** Самое тяжёлое: геотрек достаётся только реверсом приложения (хрупко, серая зона ToS). Может оказаться невыполнимым — принять как риск.
4. **Прогресс по книгам.** Приложение eBook наружу прогресс не отдаёт → ручной ввод процента (поле есть). Проверить лазейку в research-заходе.
5. **Подкасты (2/день).** Spotify API не отдаёт историю эпизодов подкастов → ручной чек или другой клиент. (Заодно: при желании начать копить recently-played в БД для ретроспективы — дёшево.)
6. **Плёночная галерея (вариант А).** Отдельный полноэкранный раздел, дроп = альбом на 36 кадров. **Зависит от админки** (нужна загрузка файлов).
7. **3D-артефакты.** Конвертация PNG → 3D/пиксель-3D, three.js. В v1 — только PNG в marquee.
8. **Админ-панель (`/admin`).** Отложена; нужна в первую очередь под загрузку плёнки, далее CRUD проектов/тем/артефактов и правки задним числом. Под тем же токеном.
9. **Геймификация.** Достижения/стрики поверх собранной статистики. Зависит от того, какие данные реально приедут.

## 7. UI-принципы

- **Календарь — главная навигация.** Ховер = превью дня, клик = перефокус «Сегодня».
- **Bento-сетка**, «Сегодня» — крупная центральная плитка, по периферии мелкие виджеты (now-playing, соцссылки, индикатор темы, лента проектов).
- **Цель — 16" без скролла** для основного борда; галереи/архивы — отдельные роуты/панели; на узких экранах — деградация в скролл.
- **Темизация через design tokens** (CSS-переменные): палитра, типографика, фон; сменяемо по релизам.
- **Артефакты — marquee с подписями.** «Монстр» и пункты чеклиста — цветовые акценты/иконки на днях.
- Честно: плотность держать под контролем — не пытаться впихнуть на главный экран всё сразу.

## 8. Безопасность

- **Транспорт:** только HTTPS (Let's Encrypt через reverse proxy).
- **Запись:** все мутирующие эндпоинты (`/api/ingest/*` и будущие admin) — за статическим bearer-токеном. GET-эндпоинты публичны.
- **Секреты at-rest:** Spotify refresh-токен и любой чувствительный секрет — **шифруются на уровне колонки** (ключ из env/секрет-стора); опционально full-disk encryption на VPS (накладные расходы пренебрежимы — «без ущерба»).
- **Токен записи:** хранить в секретах шортката и серверном env, не в репозитории; предусмотреть лёгкую ротацию.
- Поскольку контент и так публичен на чтение, главный объект защиты — **креды записи**, а не сами статы.

## 9. Этапы разработки (milestones)

- **M0 — Каркас.** Скелет Quarkus (Kotlin) + Postgres; скелет Next.js; деплой на VPS; reverse proxy + TLS + домен; bearer-аутентификация записи.
- **M1 — Спина данных.** Сущности DayRecord/Workout/Checklist; `ingest/health` + `ingest/daily`; оба iOS-шортката (Health авто + чеклист в тап); проверка, что данные текут.
- **M2 — Публичный каркас.** Bento-layout, плитка «Сегодня», календарь ±15 (ховер/клик), привязка к day-эндпоинтам.
- **M3 — Spotify.** OAuth, now-playing/recent/top, виджеты.
- **M4 — Статика и темы.** Проекты, соцссылки, hero-фото, marquee артефактов, система тем на токенах (одна тема).
- **M5 — Полировка и запуск.** Подгонка под 16", механизм смены темы, финал.
- **Бэклог-фазы:** админка + плёночная галерея → экранное время → Вуш/Юрент → книги/подкасты → 3D → геймификация.

## 10. Риски и митигации

| Риск | Митигация |
|---|---|
| Экранное время недоступно программно | Ручной ввод (поле есть); отдельный research по DeviceActivity |
| У Вуш/Юрент нет API; трек на карте может быть невозможен | Ручной факт поездки; реверс — отдельная оценка; принять, что трек может не взлететь |
| eBook не отдаёт прогресс | Ручной ввод процента |
| Spotify: только 50 недавних, нет истории подкастов | Топы для ретроспективы; подкасты вручную; при желании — копить recently-played позже |
| Фронт — слабая зона владельца | React + shadcn + помощь ИИ; админку держать утилитарной/«некрасивой»; опираться на библиотеки компонентов |
| Плотность на одном экране 16" | Приоритет Сегодня+Календарь+статы+now-playing+тема; галереи за вкладками; responsive-fallback |
| Утечка токена записи = полный write-доступ | Токен только на сервере/в шорткате, HTTPS, лёгкая ротация |
