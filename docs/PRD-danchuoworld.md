## 1. Обзор и цели

Публичный персональный сайт-дашборд на собственном домене: «живая визитка» вокруг **календаря**, где центр — **текущий день** и его статистика, а вокруг — компактные виджеты (Spotify, проекты, соцссылки, тема). Часть данных приходит автоматически (Apple Health, Spotify), часть вводится в один тап через iOS-шорткаты. Визуальный стиль («волна») сменяем по релизам в честь периода жизни.

**Цели v1:**
- Рабочее ядро «Сегодня + календарь» без застреваний на трудных интеграциях.
- Автоматизировать дешёвые источники (Health через Shortcut, Spotify через API).
- Заложить архитектуру тем («волн»), расширяемого чеклиста и адаптива с первого дня.
- Минимальная приватная аналитика посещений на своём решении.
- Сложные хотелки (экранное время, Вуш/Юрент, книги, плёнка, 3D) — высокоприоритетный бэклог, не блокируют релиз.

**Нецели v1:** геймификация, 3D-конвертация артефактов, админ-панель, загрузка фото через UI, ретроспективная история Spotify, публичный счётчик посещений, листание прошлых месяцев.

## 2. Целевая аудитория

- **Читатель (публичный):** любой посетитель домена. Только чтение. Видит публичный дашборд.
- **Владелец (один — ты):** единственный, кто пишет данные. Write-эндпоинты — только по токену. В v1 нет UI для записи (шорткаты + прямые вызовы API).

## 3. Технический стек

| Слой | Решение | Прим. |
|---|---|---|
| Backend | **Quarkus (Kotlin)**, монолит, REST JSON API | монолит сознательно |
| ORM / БД | **PostgreSQL** + Hibernate ORM Panache; миграции **Flyway** | реляционка под дневные записи |
| Frontend | **Next.js (React) + TypeScript + Tailwind + shadcn/ui** | минимизирует фронт-риск владельца |
| Архитектура | Расцепленная: фронт ↔ Quarkus как JSON API (это **не** микросервисы) | изолирует фронт в стек с лучшей экосистемой |
| Кэш | **quarkus-cache (Caffeine, in-process)** | Redis пока не нужен (см. §8) |
| Рейтлимит | **Bucket4j (Quarkus ext)** на эндпоинты + L7-лимиты в Caddy | анти-абуз, не анти-DDoS |
| Сборка | **JVM-jar + native-image** (GraalVM, под ARM/C6G) | native экономит память на маленьком боксе |
| Деплой | **Docker Compose + GitHub Actions** | авто-деплой на VPS |
| Reverse proxy / TLS | **Caddy** + Let's Encrypt | авто-HTTPS, отдача статики Next.js |
| Аналитика | **своё решение в Postgres** (JS-бикон, cookieless) | без третьих сторон |
| Авторизация записи | один статический **bearer-токен** в `Authorization` | один механизм на шорткаты и будущую админку |

**Будущая инфра (бэклог, не v1):** Cloudflare free (без капчи) перед сайтом, Redis (если понадобится шаринг кэша/лимитов), бэкапы Postgres.

**Документация:** Quarkus REST / Panache / Cache (`quarkus.io/guides`), Bucket4j Quarkus, Flyway, Next.js App Router (`nextjs.org/docs`), shadcn/ui (`ui.shadcn.com`), Spotify Web API (`developer.spotify.com/documentation/web-api`).

## 4. Семантика данных и времени

> Сквозные соглашения, обязательные для корректности. Решить до M1.

- **Канонический часовой пояс — MSK (UTC+3).** Все «дни», границы суток, агрегаты считаются в MSK независимо от tz сервера/посетителя. *(Будущее: переключатель смещения автором — улетел в другой пояс, на сайте везде показывается сдвиг.)*
- **Граница суток** — полночь MSK.
- **Сон относится ко дню пробуждения.** Смотрим 15-е → показываем сон, из которого проснулся 15-го (засыпал 14-го). `sleepMinutes` дня D = сессия сна, завершившаяся (пробуждение) в день D.
- **Генезис-дата danchuo.world** — фиксированная дата отсчёта в конфиге. Данные хранятся и показываются с неё; раньше — пусто.
- **Будущие дни** в календаре рендерятся пустыми.
- **Все данные публичны** — осознанное решение владельца.

## 5. Основные функции v1

Каждая фича: описание → acceptance criteria → technical considerations.

### 5.1. Каркас экрана (bento-сетка)
**Описание.** Главный экран — bento-сетка модульных плиток, центр — крупная плитка «Сегодня». Рассчитан на 16" (~1512px) без вертикального скролла; галереи/архивы — отдельные роуты/панели.

**Acceptance criteria:**
- На ширине ≥1440px главный борд (Сегодня + Календарь + ряд статов + now-playing + индикатор темы) виден без скролла.
- Все цвета/шрифты/радиусы берутся из активной темы (§6), не хардкодятся.

**Technical considerations.** CSS Grid; все визуальные значения — через CSS-переменные (design tokens).

### 5.2. Плитка «Сегодня»
**Описание.** Центральный фокус: крупная дата + **имя дня** + ключевые статы выбранного дня — шаги, сон, тренировка(и), отметки чеклиста, «монстр», (позже) экранное время.

**Acceptance criteria:**
- По умолчанию — сегодняшний день (MSK).
- При клике на день календаря перерисовывается на выбранную дату.
- **Имя дня** (короткий заголовок, напр. «первый забег») показывается под датой; задаётся владельцем и редактируется задним числом (см. 5.6). Если имени нет — строка не рендерится.
- Отсутствующие данные — «нет данных», не 0 и не ошибка.

**Technical considerations.** Источник — `GET /api/days/{date}`. «Монстр» = картинка банки выпитого вкуса + акцент-цвет дня (или нейтрально).

### 5.3. Календарь-навигатор (±15 дней)
**Описание.** Главное взаимодействие. Окно: текущий день ±15. Ховер по дню = мини-превью; клик = перефокус «Сегодня». Прошлые месяцы пока не листаются (бэклог).

**Acceptance criteria:**
- Видны дни (today−15)…(today+15) в MSK.
- Ховер по дню = мини-сводка без перехода; **на тач — тап** (см. 5.10).
- Клик = смена фокусного дня; дни с данными отличимы от пустых; «монстр»-дни имеют акцент.

**Technical considerations.** Диапазон одним запросом `GET /api/days?from=&to=`, кэш на клиенте.

### 5.4. Apple Health (шаги, сон, тренировки)
**Описание.** Данные из HealthKit заливаются iOS-шорткатом 12:00 / 18:00 / 24:00 MSK. Облачного API у Apple нет — пушит устройство.

**Acceptance criteria:**
- `POST /api/ingest/health` (токен) принимает за дату: `steps`, `sleepMinutes`, список `workouts`.
- Повторный POST за дату — идемпотентный upsert.
- Вечерний прогон фиксирует полный день; пропущенный прогон догоняется следующим (Health отдаёт весь день).

**Technical considerations.** Health-шорткат **без ввода** → крутится по time-automation сам. Тело — JSON.

### 5.5. Spotify (now-playing / недавние / топы)
**Описание.** Живой опрос Spotify Web API. Свою историю в v1 не копим.

**Acceptance criteria:**
- `GET /api/spotify/now-playing` — текущий трек или «ничего не играет».
- `GET /api/spotify/recent` — последние (лимит API 50); `…/top?range=short|medium|long` — топы за ~4 нед / 6 мес / всё время.
- now-playing обновляется при загрузке страницы.
- На блоке Spotify — корректная атрибуция (лого/ссылка) по dev-условиям; вид — аккуратный, в стиле волны.

**Technical considerations.** OAuth Authorization Code; **refresh-токен шифруется at-rest**. **quarkus-cache (Caffeine):** now-playing TTL ~20с, recent/top — минуты → один upstream-вызов на всех посетителей, лимиты Spotify не превышаются. Ограничение: recently-played — только 50, посуточной истории нет.

### 5.6. Чеклист дисциплины (расширяемый) + «монстр»
**Описание.** Ежедневные бинарные пункты (растяжка, чтение, …), расширяемые без релиза. Плюс **«монстр» — конкретный вкус энергетика за день** (банка с картинкой) либо «не пил»; картинка/цвет дают день акцент.

**Acceptance criteria:**
- Пункты и вкусы задаются данными (новый добавляется без деплоя).
- `POST /api/ingest/daily` (токен) за дату: отметки пунктов, `monsterFlavorKey: string|null`, **`title: string|null`** (имя дня), (позже) `screenTimeMinutes`, `readingProgressPercent`.
- **Имя дня** вводится тем же интерактивным iOS-шорткатом (Ask for Input → текст) и редактируется задним числом повторным ingest за дату (идемпотентный upsert).
- В «Сегодня» — банка вкуса + имя дня; в превью календаря — акцент монстра и маркер «есть имя» (отрисовка — по стилю активной волны, DESIGN.md).

**Technical considerations.** Ввод — **интерактивный iOS-шорткат в один тап**: меню вкусов + «не пил» + Ask for Input для чисел → POST; с домашнего экрана/виджета, опц. напоминание. v1 — один вкус на день (мультивыбор = тривиальный many-to-many). Вкусы сидятся статикой/API.

### 5.7. Проекты (компактный выпадающий блок)
**Описание.** Проекты по годам/кварталам в небольшом раскрывающемся блоке.

**Acceptance criteria:**
- `GET /api/projects` — сгруппированы/сортируемы по году и кварталу.
- Поля: заголовок, год, (опц.) квартал, ссылка, описание.

**Technical considerations.** В v1 наполняется сид-конфигом / прямым API.

### 5.8. Соцссылки + избранное фото + marquee артефактов
**Описание.** Блок соцссылок; один hero-снимок; **бегущая строка артефактов с подписями** (футболки, ракетка, камера, айфон, очки) — в v1 статичные PNG.

**Acceptance criteria:**
- `GET /api/social-links` — ссылки с иконками и порядком.
- Hero-снимок (сид-ассет); marquee бесконечно прокручивает артефакты, уважает `prefers-reduced-motion`.

**Technical considerations.** Артефакты — фиксированный набор, статика. 3D-конвертация — бэклог.

### 5.9. Система тем («волна») + переключатель
**Описание.** Стиль волны (палитра, типографика, фон, декоративный слой) сменяем по релизам. В v1 — одна волна (волна 01, DESIGN.md), архитектура готова к смене. **Переключатель волн** проектируется сразу: горизонтальный ряд квадратных иконок-свотчей волн, клик меняет стиль полностью.

**Acceptance criteria:**
- Все визуальные значения — design tokens (CSS-переменные).
- `GET /api/theme/active` отдаёт токены активной волны (default); ровно одна активна.
- Смена активной волны меняет вид всего сайта без правок компонентов.
- Переключатель: в v1 — 1 активная иконка + слоты-заглушки под будущие волны. Клик по выпущенной волне → клиентский своп токенов в `:root` (быстрый кросс-фейд), без перезагрузки.

**Technical considerations.** Токены в БД (JSONB), фронт инжектит в `:root`. Переключение — клиентское среди выпущенных волн (`GET /api/themes` отдаёт список выпущенных); канон «active» задаёт владелец. Открытый вопрос (DESIGN.md §2.6): доступно всем посетителям vs только превью — по умолчанию для всех.

### 5.10. Адаптивность и масштабируемость
**Описание.** Достойно на любом размере — от 27" до телефона, без зум-ужаса. Bento осознанно перестраивается, а не сжимается 1-в-1.

**Acceptance criteria:**
- **Desktop ≥1440px:** полный bento без скролла.
- **Tablet/Laptop 640–1439px:** 2 колонки, «Сегодня» приоритетна; скролл допустим.
- **Mobile <640px:** одноколоночный стек (Сегодня → календарь → статы → now-playing → проекты/ссылки → marquee), без горизонтального скролла страницы.
- **Календарь на тач:** ховер → тап (тап = выбор+сводка, повторный = «открыть как Сегодня»); на мобиле допустима недельная полоса.
- Тач-таргеты ≥44px; флюидные шрифты (`clamp()`); `prefers-reduced-motion`; адаптивные картинки (`next/image`).

**Technical considerations.** Mobile-first на Tailwind-брейкпоинтах. Hover-зависимый календарь обязательно с тач-эквивалентом с самого начала.

### 5.11. Аналитика посещений (минимальная, приватная)
**Описание.** Свой счётчик в Postgres: заходы в день, уники, время на странице. Без третьих сторон, cookieless. В v1 статистика приватная (только владелец).

**Acceptance criteria:**
- На публичных страницах — **JS-бикон**: POST при загрузке + добивка на `visibilitychange`/выгрузке (даёт время на странице).
- Уники считаются **суточным хэшем** `sha256(ip+ua+соль+дата)` (соль ротируется ежедневно), **сырой IP не хранится**.
- Боты фильтруются: бикон (краулеры без JS не считаются) + блоклист User-Agent + игнор без `Accept-Language`/HEAD.
- Приватная вьюха владельца: заходы/день, уники/день, среднее время. Куки не ставятся.
- Сырые события хранятся (трафик мал); агрегация — позже.

**Technical considerations.** Сущность `AnalyticsEvent` (§7). Referrer пишется в сырьё сразу, но **в UI выводится позже** (бэклог). Публичный счётчик («посетитель №N») — бэклог.

## 8. Кэширование, лимиты и эксплуатация

- **Кэш:** `quarkus-cache` (Caffeine, in-process). Кэшируем now-playing (~20с), recent/top (минуты), агрегаты дня и активную тему (инвалидация при ingest/смене темы). **Redis не нужен**, пока один инстанс; оправдан при мульти-инстансе / персистентности кэша / шаринге лимитов — или как осознанное «хочу пощупать» (бэклог).
- **Рейтлимит / анти-абуз:** L7-лимиты в Caddy + точечные лимиты на публичные GET через **Bucket4j** (in-memory). Важно: это останавливает одного шумного клиента, **не настоящий DDoS** — для последнего в бэклоге **Cloudflare free (без капчи)** перед сайтом.
- **Сборка:** JVM-jar (быстрый дев) + native-image (GraalVM, прод на ARM/C6G — экономия RAM). Dockerfile на оба.
- **Деплой:** Docker Compose (app + postgres + caddy). GitHub Actions: push в `main` → сборка образа → GHCR → ssh-деплой на VPS (`compose pull && up -d`). Секреты — в env/секретах Actions, не в репо.
- **Мониторинг свежести:** хранить `lastIngestAt`; в UI — тихий индикатор свежести; простой алерт (напр. в Telegram), если данные «застряли» дольше N часов — иначе молчаливо устаревший дашборд.
- **Бэкапы (бэклог):** cron на VPS → дамп Postgres → Google Drive (offsite).

## 10. UI-принципы

- **Календарь — главная навигация:** ховер = превью, клик = перефокус «Сегодня»; на тач — тап.
- **Bento**, «Сегодня» — крупная центральная плитка; по периферии мелкие виджеты.
- **16" без скролла** для борда; галереи/архивы — отдельные роуты; на узких экранах — осознанная перестройка в стек (5.10).
- **Темизация через design tokens** (волна 01 — §6).
- **Артефакты — marquee с подписями;** «монстр»/пункты чеклиста — акценты на днях.
- **Mobile-first и тач:** все hover-взаимодействия имеют тап-эквивалент; уважать `prefers-reduced-motion`.
- Плотность держать под контролем — не пихать всё на главный экран.

## 11. Безопасность и приватность

- **Транспорт:** только HTTPS (Caddy + Let's Encrypt).
- **Запись:** мутирующие эндпоинты (`/api/ingest/*`, будущая admin) — за статическим bearer-токеном; GET публичны.
- **Секреты at-rest:** Spotify refresh-токен и прочие секреты — шифрование на уровне колонки (ключ из env); опц. full-disk на VPS (накладные пренебрежимы).
- **Токен записи:** в секретах шортката и серверном env, не в репо; лёгкая ротация.
- **Аналитика:** cookieless, **без сырого IP** (только суточный хэш) → как правило, cookie-баннер не нужен (не юрист — при сомнениях свериться). Сырьё хранится минимально необходимое.
- Контент публичен на чтение → главный объект защиты — **креды записи**, не сами статы.

## 12. Этапы разработки (подробно)

### M0 — Каркас и деплой-конвейер
**Цель:** пустой, но задеплоенный и защищённый скелет в проде.
- Quarkus (Kotlin): REST, Panache, Postgres-датасорс, профили dev/prod, Flyway.
- Сборка в двух режимах (JVM-jar + native-image под ARM); Dockerfile на оба.
- `docker-compose`: app + postgres + caddy.
- GitHub Actions: push в `main` → образ → GHCR → ssh-деплой на VPS (`compose pull && up -d`).
- Caddy: домен danchuo.world, авто-TLS, reverse-proxy, отдача статики Next.js, базовые L7-лимиты.
- Bearer-фильтр записи в Quarkus; секрет в env.
**Exit:** открывается `https://danchuo.world` (заглушка), CI деплоит сам, защищённый POST без токена → 401.

### M1 — Спина данных и ingestion
**Цель:** данные с телефона надёжно долетают и хранятся.
- Сущности DayRecord (вкл. `title` — имя дня), Workout, ChecklistItem, ChecklistEntry, MonsterFlavor + миграции.
- Семантика времени (§4): канон MSK, сон по дню пробуждения, генезис-дата в конфиге.
- Эндпоинты `ingest/health`, `ingest/daily` (идемпотентный upsert; `ingest/daily` принимает `title` — имя дня, правка задним числом).
- iOS-шорткаты: (1) Health авто 12/18/24; (2) интерактивный чеклист+монстр+**имя дня** в один тап (+ опц. напоминание).
- Сид: пункты чеклиста, вкусы монстра.
**Exit:** ingest с телефона виден в БД; повтор не плодит дубли; пропущенный прогон догоняется.

### M2 — Публичный каркас и календарь
**Цель:** видимое ядро «Сегодня + календарь» в первой волне.
- Next.js скелет; токены активной волны (волна 01 — DESIGN.md) в `:root`; плитки и лоадеры в стиле волны (per-tile).
- Bento-layout 20×14 (DESIGN.md §3), плитка «Сегодня» (дата + **имя дня** + статы + чеклист + монстр), календарь ±15 (**числа в ячейках**, акцент монстра, маркер имени, ховер-превью + тап на тач), клик = перефокус.
- `GET /api/days/{date}`, `/api/days?from=&to=`, агрегатор дня.
- Адаптив (5.10 / DESIGN.md §8): desktop bento, mobile стек + недельная полоса, hover→tap, reduced-motion.
**Exit:** на десктопе борд без скролла, на телефоне — стек с недельной полосой; календарь переключает день; имя дня видно и редактируемо.

### M3 — Spotify
**Цель:** живой музыкальный слой без перегруза API.
- Регистрация Spotify-приложения, one-time OAuth (redirect URI, scopes); refresh-токен шифрованно.
- `GET` now-playing / recent / top; Caffeine-кэш (now-playing ~20с, recent/top — минуты).
- Виджеты now-playing/недавние/топы; аккуратная атрибуция Spotify (лого/ссылка).
**Exit:** now-playing живой, кэш гасит нагрузку, лимиты Spotify не превышаются.

### M4 — Статика, темы, аналитика
**Цель:** наполнить контент, включить смену тем и счётчик.
- Проекты (выпадающий блок), соцссылки, hero-фото, marquee артефактов (PNG, правая половина низа).
- Система тем: токены в БД (JSONB), `GET /api/theme/active` + `GET /api/themes`, инжект в `:root`; одна активная волна + **переключатель волн** (квадратные иконки-свотчи волн, клиентский своп токенов, §5.9).
- Аналитика (5.11): JS-бикон, эндпоинт сбора, `AnalyticsEvent` в Postgres, фильтр ботов, cookieless, приватная вьюха.
- Лимиты: Bucket4j на публичные GET.
**Exit:** контент наполняется сидом/API; тема меняется без правок компонентов; счётчик считает живых, не ботов.

### M5 — Полировка, адаптив и запуск
**Цель:** довести до релиза.
- Финальная подгонка 16" без скролла; вычитка мобайла на реальном устройстве.
- Индикатор свежести данных (`lastIngestAt`) + простой алерт при «застревании».
- SEO/OpenGraph/favicon; доступность (контраст AA, клавиатура, reduced-motion).
- Прогон пустых состояний: будущие дни, «нет данных», «ничего не играет».
**Exit:** danchuo.world v1 в проде, данные текут, выглядит достойно на телефоне и 16".

### Бэклог-фазы (после v1, порядок ориентировочный)
- **B1:** админ-панель (`/admin`) → плёночная галерея (дропы, вариант А).
- **B2:** экранное время (ручной ввод → research автоматизации).
- **B3:** Вуш/Юрент (факт поездки → попытка маршрутов).
- **B4:** книги/подкасты (ручной ввод → research лазеек).
- **B5:** инфра-крепость (Cloudflare free, бэкапы Postgres→GDrive, Redis при нужде).
- **B6:** 3D-артефакты, геймификация, переключатель tz, листание прошлых месяцев, публичный счётчик, рефереры, история Spotify.

## 13. Риски и митигации

| Риск | Митигация |
|---|---|
| Границы суток/tz путают статы | Канон MSK везде (§4) |
| Экранное время недоступно программно | Ручной ввод; research DeviceActivity |
| Вуш/Юрент: нет API, трек может быть невозможен | Ручной факт; реверс — отдельно; принять риск |
| eBook не отдаёт прогресс | Ручной ввод % |
| Spotify: 50 недавних, нет подкастов; публичная нагрузка | Топы для ретроспективы; Caffeine-кэш на now-playing |
| Фронт — слабая зона владельца | React+shadcn+ИИ; декоративный слой волны 01 (пиксель) — тонкий слой поверх дефолтов, база остаётся близка к shadcn; админка утилитарная |
| Декоративный слой волны (волна 01: пиксель) скатывается в китч | Правило сдержанности (DESIGN.md §1): декор только в рамках/иконках/акцентах/календаре, никогда в тексте; база чистая и AA |
| Плотность на 16" / мобайл | Приоритет Сегодня+Календарь+статы+now-playing+тема; перестройка в стек (5.10) |
| Молчаливо устаревшие данные (отвал шортката) | Индикатор свежести + алерт |
| Утечка токена записи | Токен только на сервере/в шорткате, HTTPS, ротация |
| Боты накручивают счётчик | Бикон + UA-блоклист + эвристики |
| Настоящий DDoS | Cloudflare free (бэклог) — app-лимитер не закрывает |
